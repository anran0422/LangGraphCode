# LangGraph Super-step（超步）怎么计算

## 1. 核心定义

LangGraph 中，**Super-step 表示一次执行轮次**。

可以这样理解：

> **同一轮可以并行执行的节点，属于同一个 Super-step；必须等待上一轮节点执行完成后才能运行的节点，进入下一个 Super-step。**

所以 Super-step：

- 不是按节点数量计算；
- 不是按边数量计算；
- 而是按“执行轮次”计算。

---

## 2. 怎么数 Super-step

从输入开始计算：

```text
Step 0：输入 / START 调度

Step 1：第一批可以执行的节点

Step 2：等待上一批完成后才能执行的节点

Step 3：继续等待前一轮完成后才能执行的节点

……
```

例如：

```text
START
 ├── A
 ├── B
 └── C

A → D

D、B、C → E

E → END
```

可以理解为：

```text
Step 0：输入 / START

Step 1：A、B、C
        ↑
        三个节点可以并行，所以仍然只算一个 Super-step

Step 2：D

Step 3：E

END：结束
```

因此一共经历：

```text
Step 0
Step 1
Step 2
Step 3
```

也就是 **4 个执行轮次**。

---

## 3. 两个最容易混淆的地方

### 并行节点只算一个 Super-step

例如：

```text
    A
   /
START ─ B
   \
    C
```

A、B、C 同一轮执行，所以：

```text
Step 1：A、B、C
```

不是三个 Super-step。

### END 不额外算一个 Super-step

例如：

```text
E → END
```

`END` 是图的终止标记，不是一个真正执行的业务节点。

因此不能写成：

```text
Step 3：E
Step 4：END   ×
```

而应该是：

```text
Step 3：E
        ↓
       END
```

---

## 4. 编号和“第几轮”要区分

LangGraph 的 step 编号从 `0` 开始。

所以：

```text
Step 0 = 第 1 个执行轮次
Step 1 = 第 2 个执行轮次
Step 2 = 第 3 个执行轮次
Step 3 = 第 4 个执行轮次
```

因此如果代码中看到：

```python
config["metadata"]["langgraph_step"] == 3
```

更严谨的说法是：

> **当前 Super-step 编号为 3，也就是第 4 个执行轮次。**

---

## 最终记忆

只需要记住四句话：

1. **Super-step 按执行轮次计算，不按节点数量计算。**
2. **同一轮并行执行的多个节点，只算一个 Super-step。**
3. **存在前后依赖时，后面的节点进入下一个 Super-step。**
4. **从输入开始计数，Step 0 是输入阶段；END 不额外算一步。**
