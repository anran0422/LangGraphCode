你现在可以把 LangGraph 子图记成：

一、子图作为节点
```
────────────────────

父图 State
     │
     │ 共享 Key
     ↓
   子图
     │
     │ 共享 Key
     ↓
父图 State

特点：
简单
自动传递共享字段
适合父子 State 有共同字段
```
而：

二、父图节点调用子图
```
────────────────────

父图 State
     │
     │
     ↓
  父图节点
     │
     │ 手动转换
     ↓
子图 State
     │
     ↓
   子图
     │
     ↓
子图 State
     │
     │ 手动转换
     ↓
父图 State

特点：
灵活
可以完全不同的字段名
可以完全不同的数据类型
可以自己决定输入输出怎么转换
```
所以你这个问题的最终答案就是：
```
“状态传输”两种方式都支持；但如果你说的“状态更新”是指 a,b → c,d，
并且字段名不同、类型也不同，那么不是某一种子图模式自动完成的，
而是你需要通过调用子图时的包装节点，显式完成 State 的输入/输出映射。
```
而你现在正在做的“将图添加为节点”这个案例，重点恰恰是学习：

父图和子图存在共享 State Key 时，LangGraph 如何自动完成状态的传递。

这两个知识点你现在已经碰到一起了，这里确实是 LangGraph 子图最容易混淆的地方。
