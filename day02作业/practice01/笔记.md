### 1. 我一直以为就是连接边才算是并行，没想到你这种 Command 连接也可以形成并行效果

对，你之前那个理解只差最后一点：

并行的本质不是“有没有画 edge”，而是：一个节点执行完后，是否同时激活了多个后继节点。

LangGraph 底层是按 super-step 执行的。一个节点完成后，可以把执行消息发送给一个或多个后继节点；如果多个节点在同一个 super-step 被激活，它们就会并行执行。


### 2. builder.add_edge()
官方 API 对 add_edge([A, B], C) 的定义就是：当提供多个起始节点时，要等待所有起始节点完成后才执行目标节点。

builder.add_edge(
        ["node_add",
         "node_mul",
         "node_sub",
         "node_div"], END
    )
意思是：全部执行完才去执行 END。
这里只有可能两个节点完成，所以不要这么写。

### 3. 什么时候在节点函数中添加 State 状态？
这里你可以先记一个非常简单的规则：

只要这是一个 LangGraph 的普通节点函数，就建议保留 state: State；
至于要不要真正读取 state，看这个节点有没有用到状态。

#### 3.1 读取 State : 需要 state
def node_1(state: State):
    x = state["x"]

#### 3.2 更新 State : 需要 state

例如：

def node_add(state: State):
    return {
        "add_res": state["x"] + 2
    }
合并回整个 State。节点应该返回 State 更新，而不是直接修改传入的 State。

#### 3.3 只负责路由，不更新 State  : 需要 _state
def node_odd(_state: State):
    return Command(
        goto=["node_add", "node_mul"]
    )
读取 State：❌
更新 State：❌
控制流程：✅

所以它只是一个路由节点。
因为它依然是一个 StateGraph Node。为了让节点接口保持统一，我建议你写成：
_state 意味着： 
LangGraph 会给我 State，但这个节点目前不需要使用。

#### 3.4 ：既读取、又更新、又路由  : 需要 State
这是 Command 很典型的用途。

def node_1(state: State) -> Command[
    Literal["node_even", "node_odd"]
]:
    x = state["x"]
    if x % 2 == 0:
        return Command(
            update={"x": x + 10},
            goto="node_even"
        )
    return Command(
        update={"x": x + 20},
        goto="node_odd"
    )
官方也特别推荐：当一个节点需要同时“更新 State + 决定路由”时使用 Command。


### 4. 定义 State
因为这里只有输入 x，后面的才有意义
class State(TypedDict):
    x: int
    add_res: NotRequired[int]
    mul_res: NotRequired[int]
    sub_res: NotRequired[int]
    div_res: NotRequired[float]
